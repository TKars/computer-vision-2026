## На чём выполнен анализ

Просмотрены все 345 названий; каждому назначена группа ручного смыслового обзора. [class_groups.json](class_groups.json) содержит 31 такую группу и отдельные гипотезы о похожих классах. Группы обзора не являются новой разметкой или обязательной иерархией модели.

Проверены все 59340 неупорядоченных пар на прежнем полном val: 103500 рисунков, по 300 на класс. Основной источник — лучший одиночный pretrained ViT, EMA эпохи 6, без TTA: 78549 верных, accuracy 75.8928%. Для проверки устойчивости использованы тот же ViT с flip TTA, лучший EfficientNet-B3 с flip TTA и сохранённые предсказания лучшего ансамбля.

Для каждой пары посчитаны направленные ошибки A → B и B → A, соседство в top-2, близость скоров в top-2, cosine между двумя столбцами вероятностей на всех 103500 рисунках и средняя вероятность противоположного класса. Cosine здесь описывает поведение классификатора, а не смысл текстовых названий.

Близкими считаются top-2, когда правильная метка входит в эту пару, `(p1-p2)/(p1+p2) <= 0.2` и `p1+p2 >= 0.25`. Это исключает бессмысленное сравнение двух очень маленьких вероятностей. Число близких top-2 включает как правильные, так и ошибочные top-1.

Отдельный процесс проверил все 345 поклассовых счётчиков и все 59340 пар для каждой из трёх моделей. Top-2/top-3 перепроверены через ранг вероятности настоящего класса без сортировки. Контрольные суммы 19 файлов совпали на ПК и Mac. Данные и разбивка не менялись, обучение не запускалось.

## Что добавил просмотр названий и изображений

Есть несколько разных причин путаницы.

1. **Пересечение смысла меток.** `cake / birthday cake`, `cup / coffee cup / mug`, `bus / school bus`. На выбранных реальных ошибках свечи встречаются у обоих названий тортов; рисунки чашек и кружек часто не дают очевидного различия. Это не доказывает ошибочность меток и не даёт оценки доли неоднозначных примеров, но показывает риск усиленного обучения на самых уверенных ошибках.
2. **Нужна мелкая отличительная деталь.** `guitar / violin / cello`, `hexagon / octagon`, `pickup truck / truck`. У части выбранных многоугольников контур не замкнут или стороны прорисованы неясно. Стоит проверить сохранность таких деталей после аугментаций и масштабирования.
3. **Похожие формы при разном смысле.** `broccoli / tree` — 88 взаимных ошибок; `bush / cloud` — 63; `feather / leaf` — 60; `pizza / wheel` — 37; `camera / washing machine` — 26; `microphone / tennis racquet` — 25. Одной смысловой группировкой такое не поймать.

Граф устойчивых ошибок нашёл 56 сообществ. Ребро добавлялось при не менее 20 взаимных ошибок у plain ViT и не менее 15 у ViT flip и B3 flip; вес ребра — число ошибок plain ViT. Внутри найденных сообществ 7371 ошибка, 29.54% всех ошибок ViT. Это описательная группировка, не доказанная иерархия: например, овальные объекты связывают еду, водоёмы и ванны. Не следует жёстко направлять такую группу в отдельную ветку классификатора.

[Примеры ошибок](output/class-analysis-final-20261015/confusion_examples.png) — по два самых уверенных ошибочных рисунка в каждом направлении для десяти крупнейших пар. Они намеренно отобраны по уверенности и не являются случайной выборкой.

## Что это означает для цели 80%

У plain ViT 24951 ошибка. Для 80% нужны ещё 4251 верный ответ без потери уже правильных.

- Правильная метка есть в top-2 у 89387 рисунков: **86.3643%**. В 10838 ошибках она занимает второе место. Для 80% пришлось бы исправить чистыми 39.22% этих ошибок. Это верхняя граница с использованием настоящих меток, не результат реализованного алгоритма.
- Условие близких скоров выделяет только 2655 ошибок. Даже идеальное исправление всех них без единой новой ошибки дало бы **78.4580%**. Одного переключателя для неуверенных top-2 по этому критерию недостаточно.
- Есть 3960 ошибок со score победителя не ниже 0.8. Высокий softmax-score не означает правильную метку; нельзя считать такие train-примеры автоматически полезными hard negatives или автоматически ошибочной разметкой.
- Десять худших классов содержат 1766 ошибок, двадцать — 3271. Даже полностью исправленные двадцать худших классов дали бы только **79.0531%**. Тридцать худших содержат 4607 ошибок: для 80% понадобилось бы исправить более 92% их ошибок, не потеряв ничего снаружи.
- Десять крупнейших пар дают 1250 ошибок. Следовательно, работа только с несколькими названиями не закрывает разрыв до 80%: нужно улучшать представления и более широкий набор различений.

## Как использовать результаты

### 1. Базовый ViT на 95/5

Сначала получить baseline на новой фиксированной стратифицированной разбивке. Предлагается сохранить по 100 рисунков каждого класса из прежнего val, остальные 200 перенести в train: 655500/34500. Исходные файлы сохранить, записать индексы и seed. Добавится 69000 train-примеров, то есть 11.76%; это полезное изменение объёма данных, но не доказательство прироста до 80%.

Начать с внешних pretrained-весов и зафиксировать остальные условия. Сохранённый старый checkpoint пересчитать на этих же 34500, чтобы сравнение было парным. После переноса 69000 примеров в train прежние 103500 больше не использовать как честный val новой модели. Меньший val уже использовался в подборе прошлых моделей и теперь имеет только 100 примеров на класс; мелкие колебания отдельных классов трактовать осторожно.

### 2. Целевое различение соседних классов в одной модели

Следующий отдельный эксперимент — глобальная cross-entropy на 345 классов плюс небольшой дополнительный loss внутри списка сложных соседей настоящего класса. Например: `L = CE_345 + lambda * CE_neighbors`, где соседями считаются несколько устойчиво путающихся классов, а не всё связное сообщество. Это можно считать на тех же logits, без второго backbone и без ансамбля.

Начальная гипотеза — lambda около 0.1. Глобальный loss, единая голова на 345 классов и обычный inference сохраняются. Конкретный коэффициент не проверялся. Сравнить с baseline при одинаковых данных, начальных весах и бюджете; оценивать общий accuracy и изменения ошибок конкретных пар.

### 3. Батчи с трудными соседями, а не перевес всех плохих классов

Классы уже сбалансированы. Простое повышение весов слабых классов не исправляет дисбаланс и может ухудшить остальные. Более адресный вариант: большая часть батча остаётся обычной, меньшая формируется из похожих классов — например, скрипок и гитар, автобусов двух типов, разных грузовиков. Внутри них сохранять разные реальные train-рисунки, включая обычные, а не выбирать только максимальный loss.

Ориентир для отдельного теста — 75% обычных примеров и 25% примеров из трудных соседей. Не менять sampling и loss одновременно с первым baseline. Данные val/test не использовать для градиентных обновлений.

### 4. Проверить аугментации и неоднозначность

Текущие преобразования выполняются на 28×28 до увеличения входа. Проверить на train, не обрезаются ли края и не исчезают ли углы, струны, грифы, ручки и элементы кузова после масштаба и сдвига. Кандидат для отдельного сравнения — преобразования с сохранением полного контура и более мягким масштабированием. Больший апскейл сам по себе не возвращает потерянную информацию.

Для наиболее пересекающихся по смыслу пар провести небольшой ручной аудит train. Не объединять классы, не менять val-метки и не удалять примеры автоматически из-за несогласия модели. Пока оставить label smoothing 0.05 в baseline; его изменение проверять отдельно, если потребуется.

Порядок следующей работы: **95/5 baseline → один тест дополнительного loss для соседей → по результату sampling или аугментации**. Никакой из вариантов пока не обучен; 80% остаются целью.
